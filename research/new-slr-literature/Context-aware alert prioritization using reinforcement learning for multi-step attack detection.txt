Abstract
Alert fatigue problems can have serious consequences for the enterprise security. When analysts become overwhelmed by the sheer number of alerts, high-risk alerts may go unnoticed or receive delayed responses, exposing the organization to potential cyber threats or data breaches. While current research on alert triage primarily concentrates on reducing false positives, analysts still face a shortage of resources to investigate all true alerts. The key to resolving this issue lies in the prioritization of alerts based on their potential severity, allowing analysts to allocate their efforts effectively.
This paper introduces AlertPro, an alert prioritization framework that facilitates the alert triage and validation stage of typical SOC workflow. The AlertPro framework extracts context features from alert sequences and history features from alerts previously investigated by analysts, besides basic features from raw alert data. By presenting analysts with only the top-ranked potentially high-risk alerts in each query and continually updating these rankings based on feedback, AlertPro significantly streamlines the alert investigation process. To evaluate AlertPro, we conducted experiments on five datasets that are chosen or prepared specifically because they all include multi-step attacks. The results reveal that AlertPro is able to discover a previously undisclosed attack concealed within the public dataset iscx, illustrating its potential in enhancing security posture. We also evaluate the feature importance in anomaly detection and conclude that employing context features yields better performance over basic features. The paper also explores the effectiveness of incorporating history features in active learning, achieving an average improvement of 30% in attack discovery rates. The processing time of AlertPro for re-ranking and selecting high-risk alerts is within 0.5 seconds, indicating that AlertPro can effectively work in real-time scenarios. AlertPro is limited to only using partial feedback and can be improved by incorporating richer feedback from experts. Overall, AlertPro mitigates alert fatigue, enabling security analysts to concentrate their efforts on high-priority threats.

Introduction
The Security Operations Center (SOC) is responsible for ensuring the security of the enterprise network, with a specific focus on efficiently detecting and responding to Advanced Persistent Threat (APT) attacks. An illustrative example of APT attacks is the campaign of TA4591 in 2017, operated by a financially oriented attack group. In this campaign, the attacker gained initial access by exploiting a vulnerability CVE-2017-0199 in Microsoft Word. The attacker's tactics involved delivering a malicious Microsoft Word document via phishing emails. Once the victim opened the document, the download of the file power.rtf was triggered. This file is actually an HTML Application (HTA) file that could download a PowerShell script named power.ps1. Subsequently, this PowerShell script was leveraged to fetch and execute the ZeroT payload cgi.exe, which, in turn, fetched and installed the PlugX Remote Access Trojan (RAT). The RAT trojan effectively collected information about the compromised system and transmitted it back to the Command and Control (C&C) server using HTTP protocol. Throughout this multi-step attack process, various alerts were generated by intrusion detection software, including the Phishing Email Detection System, Network Intrusion Detection System (NIDS), and Endpoint Detection and Response (EDR). These alerts generated during such attacks consisted of a mixture of true positives, false positives, and duplicate alerts. A survey conducted by FireEye (2015) indicates that over half of these alerts are false positives, with more than one-third being redundant. This flood of alerts is collected in the SOC, and security analysts in SOC are responsible to investigate these alerts and determine whether the network is under attack.
Alert fatigue leads to the ineffectiveness of SOC operations. When analysts are constantly inundated with alerts, it becomes increasingly challenging for them to prioritize and respond to attack alerts in a timely manner. The data breach incident at Target (Riley et al., 2014) serves as an example of the impact of alert fatigue. Overwhelmed by the sheer volume of alerts, Target's SOC analysts failed to recognize crucial warnings from their anti-intrusion software, leading to the devastating data breach incident. The efficiency of analysts across various organizations can be hindered by alert fatigue. A survey (Ponemon, 2015) indicates that organizations receive nearly 17,000 malware alerts per week, of which only 19 percent are deemed reliable, and limited analytical capabilities allow only 4 percent of those alerts to be adequately analyzed. According to the survey, the estimated economic value of lost time due to false negatives or false positives is approximately 1.27 million dollars annually. These figures underscore the pressing need for addressing alert fatigue in SOC environments.
To tackle the issue of alert fatigue, several automated alert triage techniques have been proposed. These techniques, such as alert reduction, prioritization, and correlation approaches, aim to alleviate the burden on analysts by reducing the total number of alerts, prioritizing the most critical ones, and identifying relationships among different alerts. Alert reduction (Al-Saedi et al., 2012; Njogu and Jiawei, 2010) is a process aimed at reducing the number of alerts, particularly those that are redundant due to overlapping detection capabilities of various products. One common method involves clustering similar alerts, with each class serving as a meta-alert. Alert prioritization (Ban et al., 2021; Aminanto et al., 2019; van Ede et al., 2022; Liu et al., 2022a; Veeramachaneni et al., 2016) is the process of categorizing and ranking security alerts. It involves assigning a priority or severity level to each alert, guiding security analysts on response efforts the allocation. The goal of alert prioritization is to ensure that the most critical alerts receive immediate attention and response from analysts, while lower-priority alerts can be addressed at a later time or potentially automated. By effectively prioritizing alerts, security teams can efficiently manage their workload, allocate resources, and focus on mitigating the most significant risks. Alert correlation (Ning et al., 2002; Shittu et al., 2014; Haas and Fischer, 2018; Husák and Kašpar, 2019; Nadeem et al., 2021; Hassan et al., 2019; Liu et al., 2022b) is a crucial process that involves identifying and grouping related security alerts to achieve a comprehensive understanding of potential security incidents or attacks. It involves analyzing multiple alerts from various sources and systems to determine if they are interconnected or part of a larger, coordinated attack. By correlating alerts, security teams can uncover the broader context of an incident, identify patterns, and integrate disparate pieces of information to respond effectively to complex threats. This approach enhances the SOC's ability to detect sophisticated and multi-step attacks, ultimately bolstering the organization's overall cybersecurity posture.
Drawing from the experiences of one of the authors, who worked as a triage specialist in the SOC and conducted hands-on investigations of alerts for six months, two critical insights into the alert validation process have been gained: (1) alerts with more comprehensive attack context are more likely to be critical attacks; (2) adjusting alert triage results based on expert feedback can reduce subsequent false positives and false negatives.
Based on these two insights and a thorough review of existing research, two research gaps are identified. First, current methods for analyzing alerts primarily concentrate on the alerts themselves, often overlooking the broader attack context. This is particularly problematic when considering multi-step attacks (Navarro et al., 2018a) or APT campaigns, which have contextual correlations between attack steps and are difficult to evaluate based solely on the alert's attributes (Zhang and Ma, 2022). For example, an AWVS Port Scan alert might initially seem insignificant, but when accompanied by an Exploit CVE-2020-14750 on Oracle Weblogic Server alert, it becomes critical. Second, existing detection methods lack the capability to automatically update the model using expert feedback (Wang et al., 2020), thereby hindering the improvement of assessment accuracy and the prevention of future similar mistakes. Although alert triage models provide recommendations for the priority of alerts, analysts are still required to review the results and rectify any false positives or false negatives. Additionally, there is a persistent occurrence of incorrect alerts, necessitating frequent manual correction and significantly increasing the workload. This emphasizes the need for a feedback method that can effectively address these limitations.
Challenge. In summary, the challenges associated with alert ranking determination are as follows:
*
Despite extensive research on individual alerts, current studies have overlooked the contextual semantics associated with them.
*
The existing alert triage methods are not suitable for alert analysis because they fail to leverage the implicit information provided by analysts' feedback to automatically update rank results.
In this paper, we propose AlertPro, a context-sensitive and self-evolving framework to automatically learn from human experts' experience to distinguish critical alerts from non-attack or low-risk alerts. Specifically, our framework consists of two modules: a context inference module which extracts basic and context features of alerts, and a self-evolution module, which automatically updates the model to identify more critical alerts based on constant feedback.
Contribution. The contributions of this paper are the following:
*
We model the alert analysis task as a human-in-the-loop process, and use context features from the alert sequences, and history features from security experts' feedback, besides extracting basic features of alerts.
*
We propose the AlertPro framework, which uses reinforcement learning to optimize the results by re-ranking the alerts using history features from expert feedback.
*
We evaluate the performance of AlertPro using 5 real-world datasets and the results demonstrate that both contextual feature selection and feedback-based active learning models can improve detection accuracy and efficiency.
